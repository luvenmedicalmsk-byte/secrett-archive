# Architecture Overview v1 — Atlas Intelligence

**Тип:** карта верхнего уровня (НЕ ADR). Опорный документ, на который ссылаются ADR-001, ADR-002, ADR-003.
**Назначение:** зафиксировать концептуальные слои Atlas и поток от документа к аналитическому знанию, чтобы отдельные ADR ссылались на общую карту, а не переописывали её.

## Концептуальный поток

```
Источники (RSS / Telegram / фиды)
        │  документы (сырьё)
        ▼
Admission ── допуск: сигнал или шум (см. поздняя фаза ADR-008)
        │  допущенные записи
        ▼
Аналитические движки ── формируют Model(t):
   Domain · Origin · Severity · Geo · Lifecycle
        │  Analytical Model (Model(t))
        ▼
State Layer (ADR-002) ── память: хранит Model(t−1), отдаёт для сравнения
        │  Model(t−1) ↔ Model(t)
        ▼
Information Gain ── прирост знания = изменение модели между циклами (ADR-001)
   интерпретация «изменения» зависит от природы объекта (ADR-003)
        │  вердикт: есть ли новое знание
        ▼
Routing ── распределение по поверхностям
        │
        ▼
Presentation Layers ── Timeline · Карта · Risk Matrix · Страновая аналитика
```

## Слои и их назначение (концептуально)

| Слой | Назначение | ADR |
|---|---|---|
| Admission | отделяет сигнал от шума на входе | ADR-008 (поздняя фаза) |
| Аналитическая модель | вывод системы об объекте по осям (домен, риск, гео, состояние, происхождение) | Model Axes Spec |
| Object Nature | природа объекта: событие или процесс; свойство модели, владелец Lifecycle | **ADR-003** |
| State Layer | память аналитической модели: хранит Model(t−1) | **ADR-002** |
| Information Gain | прирост знания = сравнение Model(t−1) ↔ Model(t) | **ADR-001**, IG Function/Engine Spec |
| Lifecycle | идентичность, возраст, природа, жизненный цикл объекта | ADR-003 (владелец), ADR-009 (переходы) |
| Routing | распределение по поверхностям представления | (Open) |
| Presentation | Timeline / Карта / Risk Matrix / страновая аналитика | — |

## Ключевые принципы карты

- **Единица ценности — знание, не документ.** Timeline публикует прирост аналитического знания (ADR-001), а не поступление записей.
- **Система наблюдает свои выводы, а не мир напрямую.** Сравнивается Model(t−1) ↔ Model(t), поэтому необходима память (State Layer, ADR-002).
- **Природа объекта определяет смысл «изменения».** Событие и процесс требуют разной трактовки прироста знания (ADR-003).
- **Разделение ответственности.** State Layer помнит, Information Gain сравнивает, Lifecycle владеет идентичностью/природой, Routing распределяет — ни один слой не делает работу другого.

## Отношение к реализации (важно для читателя)

Эта карта и ранняя серия ADR-001–003 описывают **целевую концептуальную архитектуру** Atlas. Текущая реализация в `scripts/fetch_events.py` и `scripts/signal_engine.py` (и поздняя серия ADR-004–009) — это **воплощение того же конвейера** инженерными средствами. Соответствия неполные и намеренно не буквальные:

- роль **Information Gain Layer** сегодня распределена между Admission (что допускать) и Process Engine + lifecycle-gate (что считать новым развитием, а что переподтверждением) — отдельного одноимённого модуля в коде нет;
- **State Layer** реализован как предыдущий `signals.json` + severity_history процессов, а не как выделенное хранилище;
- **Object Nature** в поздней фазе проявляется через долгоживущие процессы vs дискретные события (ADR-009);
- **Routing** ≈ квоты доменов + feed_visible/analytic-слой.

Читателю не следует искать в коде буквальный «Information Gain Layer» — искать нужно связку Admission + Process Engine + lifecycle-gate, выполняющую его функцию.
