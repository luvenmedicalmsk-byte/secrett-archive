# ADR-002 — State Layer: память аналитической модели Atlas

**Статус:** принято
**Основание:** ADR-001 (Timeline публикует новое аналитическое знание), Architecture Overview v1, Validation Report (State Layer — обязательное условие полного Information Gain)
**Область:** назначение и ответственность State Layer; не спецификация хранения, не алгоритмы

## 1. Назначение State Layer

State Layer — память аналитической системы: компонент, сохраняющий предыдущую аналитическую модель каждого наблюдаемого объекта, чтобы следующий цикл обработки мог сравнить «что система знала» с «что знает теперь».

**Почему без него невозможен полный Information Gain.** Information Gain определён (ADR-001, Overview) как результат сравнения Model(t−1) и Model(t). Сравнение требует, чтобы Model(t−1) существовала к моменту обработки Model(t). Без сохранённого прошлого система располагает только текущим снимком и вынуждена аппроксимировать прирост знания по косвенным признакам (подтверждено Validation Report). State Layer — это тот компонент, который делает Model(t−1) доступной; без него сравнивать нечего.

**Почему это память модели, а не хранилище документов.** State Layer хранит не то, что поступило, а то, что система об объекте вывела. Он не архив входящих записей и не лента событий — это состояние понимания системы.

Разграничение четырёх сущностей:

| Сущность | Что это |
|---|---|
| Документ | входящая запись из источника (RSS/Telegram/фид); сырьё |
| Событие | факт в мире, о котором сообщает документ |
| Аналитическая модель | вывод системы об объекте: как система его оценивает по своим осям |
| Состояние системы | совокупность аналитических моделей всех наблюдаемых объектов на момент времени |

State Layer хранит аналитические модели и тем самым удерживает состояние системы между циклами. Документы и события — вне его ответственности; они принадлежат более ранним слоям конвейера.

## 2. Ответственность

**Единственная ответственность:** сохранять аналитическую модель объекта по его стабильной идентичности и предоставлять её как Model(t−1) в следующем цикле.

**Обязан делать:** принимать текущую аналитическую модель на сохранение; отдавать ранее сохранённую модель по идентичности; сохранять неизменной историю прошлых моделей.

**Принципиально НЕ должен делать:** сравнивать модели или вычислять прирост знания (это Information Gain); решать, где отображать объект (Routing); определять идентичность/возраст/стадию (Lifecycle); изменять или интерпретировать содержимое модели (хранит, но не судит).

**Проверка непересечения:**

| С компонентом | Граница |
|---|---|
| Lifecycle | владеет идентичностью и возрастом; State Layer использует идентичность как ключ, но не устанавливает её |
| Information Gain | сравнивает модели; State Layer хранит и отдаёт их, не сравнивая |
| Routing | распределяет по поверхностям; State Layer его результата не касается |
| Presentation Layers | поверхности отображают; State Layer им напрямую не служит и от них не зависит |

## 3. Что считается Model(t)

Model(t) — аналитический вывод системы об объекте на момент цикла t, сформированный движками конвейера (Domain, Origin, Severity, Geo, Lifecycle) к точке Analytical Model из Architecture Overview.

**Что входит (категориями, не полями):** отнесение к домену; оценка величины риска и её составляющих; географическая модель; состояние объекта во времени (стадия/фаза как аналитический признак); атрибуция происхождения.

**Что не входит:** сырой текст документа и форматирование; метаданные источника; данные отображения; вердикты последующих слоёв (прирост знания, маршрут) — они производны и вычисляются, а не хранятся.

**Почему именно модель — единица сравнения.** Система не наблюдает объект в мире напрямую; она наблюдает свои выводы о нём. Прирост знания — изменение вывода, а не документа. Поэтому сравнивать корректно только модели: Model(t−1) ↔ Model(t). Прямое следствие ADR-001.

## 4. Что хранится между циклами

State Layer хранит минимально необходимое для сравнения моделей — категории (не поля): **идентичность объекта** (стабильный признак, связывающий Model(t−1) и Model(t)); **оценочные оси модели** (величина риска, состояние процесса, география воздействия, последствия, уровень эскалации).

**Минимальность как принцип.** State Layer хранит только категории, участвующие в сравнении. Метаданные отображения, lifecycle-служебное, производные вердикты — вне его зоны. Конкретный состав осей — Open Question (§8).

## 5. Жизненный цикл модели

| Переход | Когда |
|---|---|
| Появление | объект впервые получил аналитическую модель |
| Обновление | сформирована новая Model(t) для наблюдаемого объекта |
| Становится предыдущей | по завершении цикла текущая модель занимает место Model(t−1) |
| Прекращение существования | объект более не наблюдается; модель выводится из состояния |

Этот ADR определяет моменты переходов, но не сроки хранения, retention или устаревание — они принадлежат реализации.

## 6. Архитектурные инварианты

- **Детерминированность** — по идентичности State Layer всегда возвращает одну и ту же модель; чтение не зависит от порядка/контекста.
- **Неизменяемость истории** — сохранённая модель не переписывается задним числом; новый цикл добавляет новое состояние.
- **Независимость от UI** — не знает о поверхностях, не обслуживает их напрямую.
- **Независимость от источников** — хранит модель, а не сырьё.
- **Независимость от Routing** — результат маршрутизации не влияет на хранимое.
- **Отсутствие аналитических решений** — не судит, не сравнивает, не классифицирует; только помнит.

## 7. Зависимости

**Использует:** идентичность объекта (от Lifecycle) — как ключ хранения.
**Используют:** Information Gain — читает Model(t−1) для сравнения с Model(t).
**Обязательная зависимость:** стабильная идентичность объекта.
**Принципиально отсутствуют зависимости:** от источников/Admission/Domain/Severity/Geo (они формируют модель до State Layer, но он зависит только от результата); от Routing и Presentation; от Information Gain как логики (IG — потребитель).

## 8. Open Questions

Сознательно не решаются: физическая реализация хранения; формат сериализации; формальный контракт Model (точный состав осей); версионирование и совместимость; миграции при изменении осей; распределённое хранение; оптимизация; retention/устаревание.

## 9. Out of Scope

Не определяет: алгоритм Information Gain, Routing, Lifecycle, API, схему данных, реализацию на Cloudflare/GitHub, код, roadmap.

ADR-002 помещает State Layer в архитектуру Atlas как память аналитической модели с единственной ответственностью — хранить Model(t−1) и отдавать её для сравнения.
