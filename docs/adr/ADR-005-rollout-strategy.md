# ADR-005 — Стратегия выката (Shadow → Canary → Production)

**Статус:** Approved · **Дата:** 2026 · **Amendment:** 09.07.2026 (переход по готовности)

## Контекст

Переключение боевого пути (legacy → canon) на живом потоке нельзя делать разом: ошибка
классификации на проде ломает ленту, процессы, аналитику. Нужен безопасный порядок с
возможностью авто-отката и наблюдением на реальной вариации потока.

## Решение

**Пайплайн выката для каждого механизма:**
```
Shadow (READ-ONLY, рядом с legacy)
  → Shadow Stable (доказано отсутствие регрессий за несколько прогонов)
  → Offline Dry Run (сравнение legacy vs canary на живых данных, без публикации)
  → Canary по доменам
  → Full Production Switch
  → Legacy Removal
```

**Порядок доменов:**
```
climate → economy → geopolitics → technology → society → Full Production → Legacy Removal → Atlas Canon v1
```

**Авто-rollback (per-domain, жёсткие числовые пороги):**
- churn > 20% (потеря/пересоздание процессов домена сверх нормы);
- born_anew > 30% (необъяснимые новые процессы);
- (для Lifecycle Canary) False Decay > 0; Continuity < 100%.

**Изоляция:** события НЕ в canary-домене классифицируются legacy без изменений.
Несколько Canary на одном домене (A2 «тип», Lifecycle «severity/health») — независимы.

## Amendment (09.07.2026) — Переход по готовности вместо фиксированного времени

**Заменяет** пункт о фиксированном 72-часовом окне перед переходом к следующему домену.

**Мотивация.** Фиксированное время привязывало переход к календарю, а не к поведению
системы. При cron каждые несколько часов важна не длительность, а то, что критерии
стабильности держатся на **реальной вариации потока** через несколько последовательных
прогонов.

**Правило.** Stage считается завершённым только если **одновременно**:
1. все активные Canary данного домена прошли свои критерии стабильности (A2 и Lifecycle —
   каждый проверяется отдельно; Stage не завершён, пока не прошёл каждый);
2. rollback не срабатывал ни разу за период наблюдения;
3. harmful-регрессий нет (neutral / beneficial допустимы);
4. identity сохранена (Lifecycle Continuity 100%, born_anew ≈ 0, first_seen не теряется);
5. churn остаётся стабильным между последовательными прогонами — низкий и без признаков
   роста (порог отката 20% остаётся ЕДИНСТВЕННОЙ жёсткой числовой нормой; отдельного
   числового порога готовности не вводится, чтобы не плодить забываемые константы);
6. выполнен минимум последовательных успешных прогонов наблюдения — несколько подряд,
   на разной вариации потока (не один снимок);
7. Morning Audit = PASS;
8. закрыты все bugfix'ы, определённые как предусловия следующего домена (Conditional GO
   из его Architecture Design);
9. Dry Run следующего домена = PASS (offline: churn / identity / born_anew / non-domain чисты).

## Следствия

- Переход между доменами — событие готовности, а не таймер.
- Каждый Canary несёт отдельную ответственность за свой критерий.
- Что не меняется: пороги авто-rollback, последовательность доменов, принцип изоляции.
