# ADR-006 — Coverage Canonizer: диагностика, а не ворота; Admission Purity отдельно

**Статус:** Approved · **Дата:** 2026

## Контекст

Возникал соблазн трактовать «покрытие каноном» (доля событий с определённым canon_type)
как ворота качества: если тип не найден → дефект. Это ошибочно смешивает две разные вещи:
полноту реестра типов и чистоту допуска событий в аналитику.

## Решение

**Coverage Canonizer = диагностика реестра, НЕ ворота.**
- `unknown` — **валидный результат**, а не дефект. Если специфичный тип не найден, событие
  получает `canon_type = unknown`; SH-U (unknown-registry) накапливает такие сигнатуры для
  последующего осмысленного расширения реестра, а не для аварийного срабатывания.
- Доменный дефолт применяется только на switch, не в тени.

**Admission Purity — отдельное качество.** Вопрос «пускать ли событие в аналитику» решает
Admission Engine (ADR-008), а не Canonizer. Покрытие каноном и чистота допуска измеряются
и развиваются независимо.

**Canonizer → maintenance mode.** После достижения Shadow Stable канонизатор переводится в
режим обслуживания: изменения только bugfix или отдельный ADR, не потоковая доработка.

## Следствия

- Низкое «покрытие» (напр. 76%) — не повод для отката; это состояние реестра, а unknown
  честно отражает границы known-типов.
- Coverage-метрика в shadow-отчёте — ориентир, не gate.
- Разделение Canonizer / Admission убирает ложную связку «нет типа → отклонить событие».
