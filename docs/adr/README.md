# Реестр архитектурных решений (ADR) — Atlas Intelligence

Каждый ADR фиксирует одно архитектурное решение: контекст, решение, следствия. Номера
неизменны. Отменённые решения не удаляются, а помечаются `Superseded` со ссылкой на замену.

| ADR | Название | Статус |
|-----|----------|--------|
| [ADR-004](ADR-004-canonical-event-model.md) | Каноническая модель события / процесса / причинного графа | Approved |
| [ADR-005](ADR-005-rollout-strategy.md) | Стратегия выката (Shadow → Canary → Production) + Amendment: переход по готовности | Approved |
| [ADR-006](ADR-006-canonizer-coverage-vs-admission.md) | Coverage Canonizer — диагностика, а не ворота; Admission Purity отдельно | Approved |
| [ADR-007](ADR-007-geo-responsibility-split.md) | Разделение ответственности GEO (resolve_geo vs _process_place) | Approved |
| [ADR-008](ADR-008-signal-purity-contract.md) | Контракт чистоты сигнала (N1 ∧ N2 ∧ N3) | Approved |
| [ADR-009](ADR-009-lifecycle-contract.md) | Контракт жизненного цикла долгоживущего процесса (LL-1..LL-9) | Approved |

## Ключевой принцип

Корень исторических ошибок классификации — **отсутствие канонической модели события**:
каждый этап пайплайна пере-выводил смысл события своим regex. ADR-004 вводит единую модель;
ADR-006/007/008/009 закрепляют ответственность отдельных слоёв; ADR-005 задаёт безопасный
порядок внедрения (теневой прогон → канареечный по доменам → продакшн).
