# Реестр архитектурных решений (ADR) — Atlas Intelligence

Каждый ADR фиксирует одно архитектурное решение: контекст, решение, следствия. Номера
неизменны. Отменённые решения не удаляются, а помечаются `Superseded` со ссылкой на замену.

Реестр проходит **две фазы**. Ранняя (001–003) описывает *целевую концептуальную
модель* Atlas на языке Information Gain / State Layer / Object Nature / Lifecycle. Поздняя
(004–009) описывает *инженерную реализацию* конвейера на языке Canonical Event / Rollout /
Canonizer / GEO / Signal Purity. Обе — об одной системе с разных уровней; мостики между
фазами указаны ниже.

## Мостики между фазами

Ранняя и поздняя серии касаются одной территории под разными углами:

- **ADR-003 Object Nature ↔ ADR-009 Lifecycle Contract** — 003 квалифицирует природу объекта (событие/процесс) как свойство; 009 описывает темпоральные переходы объекта непрерывной природы (New / Re-confirmation / Escalation / End), где переиздание источником не есть новое развитие (LL-9). Две грани владения Lifecycle.
- **ADR-002 State Layer ↔ ADR-009** — сравнение Model(t−1) ↔ Model(t) реализуется через severity_history / last_seen / evidence_count долгоживущих процессов.
- **ADR-001 Information Gain ↔ ADR-008 Signal Purity** — «новое знание vs повторение» конкретизируется контрактом N1 событийность ∧ N2 риск-релевантность ∧ N3 фактичность.

## Ключевой принцип

Корень исторических ошибок классификации — **отсутствие канонической модели события**:
каждый этап пайплайна пере-выводил смысл события своим regex. Ранняя фаза (001–003) задаёт,
*чем является знание/объект*; ADR-004 вводит единую модель события; ADR-006/007/008/009
закрепляют ответственность слоёв; ADR-005 задаёт безопасный порядок внедрения (теневой
прогон → канареечный по доменам → продакшн).

## Отношение к коду

Ранняя фаза описывает целевую концепцию; часть её компонентов (Information Gain Layer,
State Layer, Routing) в текущем коде не существуют как одноимённые модули, а реализованы
связкой Admission + Process Engine + lifecycle-gate + предыдущий signals.json. Подробнее —
в разделе «Отношение к реализации» [Architecture Overview v1](Architecture-Overview-v1.md).
